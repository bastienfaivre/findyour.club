## Successes

1. **100% story completion with growing test suite** — 265 tests at epic close (up from 187), zero regressions across stories.
2. **Epic 1 action items largely followed** — A1 (quality gates), A2 (security checklist), and A4 ("simplest approach?") were consistently applied. Code review caught race conditions, XSS vectors, and rollback edge cases.
3. **Strong email patterns established** — Email-before-update (rejection) and compensating rollback (approval) are well-tested, reusable patterns for future email flows.
4. **Clean i18n infrastructure** — Type-safe translation keys with compile-time enforcement. Adding a new language or key is straightforward and error-resistant.
5. **Consistent Server Action patterns** — Typed `{ success: true } | { success: false; error: string; code: 'SCREAMING_SNAKE_CASE' }` return type used uniformly across all actions.

---

## Challenges

1. **Story 2.0 was exceptionally large** — 60+ files modified, 727-line story file, multiple scope extensions (Turnstile, location proxy, Swiss canton data). This was necessary infrastructure but stretched the single-story model.
2. **A3 (resilience review) not automatically applied** — Race conditions and edge cases were still caught in code review rather than designed upfront. The resilience review should be a mandatory code review gate, not just a dev-side aspiration.
3. **Pre-existing test failures still unfixed** — The 3 test failures from Epic 1 (redirect mismatch) have been carried through two full epics. Low effort to fix but keeps getting deprioritized.

---

## Key Insights

1. **Resilience review must be a reviewer gate** — A3 should not rely on the dev remembering to do it. The reviewer must explicitly verify resilience paths are documented and handled before approving.
2. **Large infrastructure stories should be split proactively** — When a story touches 60+ files or spans multiple domains (i18n + schema + UI + API), split it before starting. The cost of mid-story scope extensions is real.
3. **Email patterns are now mature** — Both "email-then-update" (rejection) and "transaction-then-email-with-compensating-rollback" (approval) are well-tested. Future email stories can reference these directly.

A significant product vision shift occurred between Epic 2 completion and this retrospective:

- **From**: Website builder platform for clubs
- **To**: Worldwide directory and discovery hub for clubs
- **Key changes**: "The directory is the product" — free for all clubs, donation-funded civic infrastructure
- **New FRs**: FR47 (external website link for clubs with existing sites), FR50 (donation/support page)
- **Deferred**: FR8 (custom domains) moved to Post-MVP
