## Successes

1. **SSR-first architecture** — Every public page is a server component. No client-side data fetching for main content. Guarantees SEO crawlability, eliminates hydration mismatches, and keeps the codebase simple.

2. **100% story completion with zero regressions** — All 8 stories delivered, test suite grew consistently, no existing tests broken.

3. **Accessibility baked in from the start** — WCAG 2.1 AA patterns (semantic HTML, aria-labels, keyboard focus indicators, skip links) integrated into every story, not bolted on afterward.

4. **i18n patterns scaled effortlessly** — The `resolveUILang` → `getTranslations` → render pattern from Epic 2 worked across all 8 stories and 4 languages without issues.

5. **Code review culture caught a real XSS vulnerability** — JSON-LD output in Story 3.3 had unescaped `</script>` breakout risk, caught and fixed in review.

6. **Quality gates fully adopted** — `tsc --noEmit && lint && build` consistently applied before marking stories done (Epic 2 action item A1).

7. **URL-driven filtering pattern** — Story 3.2's `useSearchParams` + `useRouter` approach with `loading.tsx` for instant skeletons established a clean, reusable pattern.

8. **Dub.co-inspired layout** — The centered layout (max-w-[1000px], sticky navbar, standard footer) gives the platform a modern, professional look.

---

## Challenges

1. **Mid-epic design pivot (sidebar → top navbar)** — Stories 3.3–3.4 built a `ClubSidebarNav` component, then Stories 3.7–3.8 replaced it with a top navbar. The sidebar was built, tested, and then deleted.

2. **Story 3.8 oversized polish pass** — 19 items in the polish pass: max-width change, navbar restyle, footer redesign, i18n tone changes (formal → informal in FR/DE), alignment fixes. Should have been scoped as a separate story.

3. **Hardcoded English strings** — Caught in code review in 3 out of 8 stories (CountryButton, filter labels, PoweredByBanner). Same mistake repeated three times.

4. **Layout nesting confusion** — Story 3.8 discovered double `PublicLayout` wrapping (country layout + country page both providing it). Subtle bug that's easy to miss.

5. **Theme toggle orphaned** — Story 3.6 created the `ThemeToggle` component with tests, but it was never rendered in any layout. Exists but is unused.

6. **3 pre-existing test failures still unfixed** — `setup-password.test.ts` (x2) and `magic-link-route.test.ts` (x1) expect redirect to `'/'` but code redirects to `'/my-clubs'`. Unfixed across 3 epics.

---

## Key Insights

1. **Mid-epic design pivots are healthy** — They mean we're learning from seeing real pages. But the resulting work should be scoped as separate stories, not packed into polish passes.

2. **"Layouts provide shell, pages provide content"** — Needs to be an explicit architectural rule to prevent layout nesting bugs.

3. **i18n extraction at implementation time** — Hardcoded strings should never make it to code review. Extract to translation keys during implementation.

4. **Small maintenance tasks get perpetually deferred** — The 3 test failures are a 5-minute fix that's been deferred for 3 epics. Without accountability, small debt accumulates.

5. **Epic 3 was design-focused, not mutation-focused** — The resilience review gate (Epic 2 action item A3) didn't apply heavily since all pages were read-only server-rendered. It becomes critical again in Epic 4 with admin mutations.

## Significant Discovery: MVP Scope Pivot

During this retrospective, it was revealed that the project has undergone a major MVP scope pivot affecting Epic 4 and beyond:

**What changed:**
- Epic 4 renamed from "Club Site Identity & Navigation" (7 stories) to "Club Profile Setup & Moderation" (9 stories)
- MVP is now a **single-page club profile** with fixed layout, not a multi-page CMS
- Profile fields live directly on the `Club` model as typed columns
- Application form collects profile fields that are copied to Club on approval (no duplicate data entry)
- New models: `ClubPhoto` (max 10, presigned R2 upload), `OperatorMessage` (replaces `OperatorNudge`)
- Two-flag visibility system: `isPublished` (admin) + `forceOffline` (operator override)

**Deferrals:**
- Epic 5 (Content Elements) — entirely deferred to post-MVP
- Epic 6 (Contact & Communication) — partially deferred (contact form/email relay deferred; support request remains)
- Epic 7 Story 7.7 (Operator Nudge) — removed, replaced by OperatorMessage in Epic 4
- Custom domains, accent color picker, version history — all deferred to post-MVP

**Impact on Epic 4:**
- Stories 4.2 and 4.3 rework existing Epic 2 code (application form + approval flow)
- Story 4.8 reworks Epic 3 Story 3.3 (club public page → single-page profile)
- Story 4.6 introduces new R2 presigned URL upload infrastructure
- Schema models (`Page`, `PageElement`, `ContentVersion`) retained for post-MVP expansion

**Assessment:** No epic update needed — the pivot was already incorporated into the updated planning artifacts (PRD, Architecture, Epics). The team is aligned on the new direction.
